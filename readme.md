# TeamFinder — вариант 3 «Навыки проектов»

Django-приложение для поиска команды и работы над пет-проектами. Реализованы общая
функциональность задания и вариант 3: навыки проектов, автодополнение, создание
новых навыков и фильтрация проектов.

## Что работает

- Регистрация по имени, фамилии, имейлу и паролю; вход по имейлу; выход; смена пароля.
- Генерация аватара с первой буквой имени, публичные профили и редактирование своих данных.
- Проверка уникальности имейла и телефона, нормализация телефона, проверка ссылок GitHub.
- Создание, редактирование и завершение своих проектов; участие в чужих проектах.
- Списки проектов и участников от новых к старым, по 12 записей на странице.
- Навыки проекта: добавление, создание и удаление без перезагрузки; десять подсказок по префиксу.
- Фильтрация по точному названию навыка, подсветка фильтра, сброс и сохранение фильтра в пагинации.
- Админ-панель: пользователи, блокировка, пароли, проекты, участники и навыки.
- Команда демонстрационного наполнения, автоматические тесты, Docker Compose и GitHub Actions.

## Быстрый запуск для ревьюера: Docker Compose

Нужны Docker Engine / Docker Desktop с Compose v2 и Git.

1. Скопируйте файл окружения:

   ```bash
   cp .env_example .env
   ```

   В PowerShell: `Copy-Item .env_example .env`.

2. В `.env` замените `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` своими случайными
   значениями. Остальные настройки подходят для локального запуска.
   Секрет можно получить командой:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

3. Запустите приложение:

   ```bash
   docker compose up --build -d
   docker compose exec web python manage.py seed_demo --password "TeamFinder-Demo-2026!"
   docker compose exec web python manage.py createsuperuser
   ```

4. Откройте [TeamFinder](http://localhost:8080/) и [админ-панель](http://localhost:8080/admin/).

При запуске автоматически выполняются миграции и сборка статики. Compose запускает
PostgreSQL 16, приложение под Waitress и Nginx. Статика обслуживается WhiteNoise,
аватары — Nginx. Данные PostgreSQL и аватары находятся в именованных volumes.
`docker compose down` сохраняет данные; `docker compose down -v` удаляет их.

Для диагностики: `docker compose logs web db nginx`.
Если порт базы 5432 занят, измените `POSTGRES_PORT` в `.env`, например на 5436.
Внутри Compose приложение по-прежнему подключается к `db:5432`.

## Демонстрационные данные

Команда `seed_demo` создаёт четыре обычных аккаунта и по четыре проекта для каждого
(16 проектов, достаточно для проверки пагинации), участников и навыки.
Повторный запуск не дублирует данные и не меняет существующие пароли.

| Имейл | Пользователь |
| --- | --- |
| anna@example.com | Анна Соколова |
| max@example.com | Максим Волков |
| maria@example.com | Мария Орлова |
| ivan@example.com | Иван Петров |

Пароль задаётся аргументом `--password`. В команде выше это `TeamFinder-Demo-2026!`.
Это демонстрационные данные для локальной проверки. Администратор создаётся отдельно.

## Локальная разработка

Нужны Python 3.12+ и PostgreSQL 16. Можно запустить только базу через Compose:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1

pip install -r requirements-dev.txt
cp .env_example .env
# Заполните DJANGO_SECRET_KEY и POSTGRES_PASSWORD.
docker compose up -d db
python manage.py migrate
python manage.py seed_demo --password "TeamFinder-Demo-2026!"
python manage.py createsuperuser
python manage.py runserver
```

Если PostgreSQL уже установлен, задайте его параметры в `.env` и пропустите запуск
контейнера базы. В режиме разработки `DJANGO_DEBUG=True`, адрес — http://127.0.0.1:8000/.
SQLite не используется.

## Проверки

Пользователь PostgreSQL для тестов должен иметь право создания тестовой базы.
Пользователь, создаваемый контейнером PostgreSQL, уже имеет необходимые права.

```bash
ruff check .
ruff format --check .
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py collectstatic --noinput
coverage run manage.py test
coverage report
```

В контейнере: `docker compose exec web python manage.py test`.
GitHub Actions повторяет проверки с PostgreSQL 16 при push и pull request.

Тесты проверяют регистрацию, пароли, уникальность данных, загрузку аватара,
разграничение прав, CSRF, безопасное перенаправление после входа, создание и
редактирование проектов, участие и завершение, навыки, ошибки JSON,
автодополнение, фильтрацию, пагинацию, админку и повторное демонаполнение.
При тестировании файлы аватаров сохраняются во временную папку.

## Основные адреса

| Адрес | Назначение |
| --- | --- |
| `/`, `/projects/list/` | Список проектов |
| `/project/list/` | Совместимый адрес из текста задания, перенаправляет с сохранением фильтра |
| `/projects/create-project/` | Создание проекта |
| `/projects/<id>/`, `/projects/<id>/edit/` | Просмотр и редактирование |
| `/projects/<id>/complete/` | Завершение, POST |
| `/projects/<id>/toggle-participate/` | Участие / выход, POST |
| `/projects/skills/?q=Py` | Автодополнение, GET |
| `/projects/<id>/skills/add/` | Добавление навыка, POST |
| `/projects/<id>/skills/<skill_id>/remove/` | Удаление связи с навыком, POST |
| `/users/list/`, `/users/<id>/` | Участники и публичные профили |
| `/users/register/`, `/users/login/`, `/users/logout/` | Регистрация, вход, выход |
| `/users/edit-profile/`, `/users/change-password/` | Настройки своего аккаунта |
| `/admin/` | Админ-панель |

Добавление навыка принимает JSON `{"name": "Python"}` или `{"skill_id": 1}`,
а также обычные поля формы. Успешный ответ содержит `id`, `skill_id`, `name`,
`created`, `added`, `status`. Мутации требуют действующую сессию и CSRF-токен.
Ошибки API возвращаются с соответствующим HTTP-статусом и полем `error`.

## Уточнения и изменения относительно рекомендаций

- После регистрации пользователь переходит на страницу входа. Это соответствует
  описанию функциональности и итоговому чек-листу; рекомендация об автоматическом
  входе противоречит этим двум разделам.
- `Project.skills` — ManyToMany: одному проекту нужно несколько навыков, а навык
  используется многими проектами. Указание «внешний ключ» в рекомендациях не
  соответствует множественным тегам в интерфейсе.
- Телефон не запрашивается при регистрации, поэтому до заполнения профиля он может
  быть пустым. Заполненное значение уникально; `8XXXXXXXXXX` нормализуется в
  `+7XXXXXXXXXX`. Пустое значение хранится как NULL.
- Имейл нормализуется в нижний регистр, повтор в другом регистре запрещён на уровне БД.
- Автор автоматически включается в участников и не может выйти из собственного
  проекта. Новые участники не могут вступить в закрытый проект; существующие могут выйти.
- GET на выход показывает подтверждение; сессию завершает POST с CSRF.
- Основной адрес списка — `/projects/list/`, как в стартовых шаблонах.
  Также работает `/project/list/` из текста рекомендаций.
- Редактирование профиля включает имейл согласно общему описанию.
- Блокировка пользователя запрещает вход и дальнейшие действия в старой сессии,
  но его публичный профиль и проекты остаются доступны.
- В шаблонах исправлены кодирование фильтров, состояния для гостей, подписи кнопок,
  доступность меню, отображение сообщений и обработка ошибок запросов.
  В JavaScript пользовательские строки вставляются через textContent.
- Используется только `templates_var3`; `TASK_VERSION` не требуется.
  Исходные шаблоны вариантов 1 и 2 сохранены для справки.
- Зависимости обновлены в пределах Django 5.2 LTS. Обязательные проверки паролей
  включены и в режиме разработки.

## Структура

- `users/` — модель пользователя, формы, авторизация, профили, админка и тесты.
- `projects/` — проекты, навыки, API, демонаполнение, админка и тесты.
- `team_finder/` — настройки и маршрутизация.
- `templates_var3/`, `static/` — интерфейс.
- `deploy/`, `Dockerfile`, `docker-compose.yml` — запуск приложения.
- `docs/` — исходные условия проекта и отчёт о проверке.
